# Current requirements

## Public website

Present the vision, research scope, current desktop prototype, roadmap, and contribution links. Use responsive layouts, semantic navigation, keyboard focus indicators, and reduced-motion support. Public content must clearly distinguish planned capabilities from implemented behavior. No account, medical data collection, or simulation submission is included.

## Desktop application

Preserve existing behavior: 4–256 A/C/G/T bases, one FASTA record, reversible substitutions, immutable session baseline, revision-keyed composition results, local project files, and DX12 with WARP fallback. See [desktop documentation](../../apps/simulation/README.md).

## Repository

Applications build independently. Public documentation is versioned with code. Internal business and working research documents remain outside the public repository. Generated output is excluded; desktop packages are distributed through release artifacts.
